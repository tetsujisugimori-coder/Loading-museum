# Stage Cの通信回数契約と停止監督

## 実runnerでの判定

[通信契約v1の原本](NETWORK-CONTRACT-v1.md)と[固定JSON](NETWORK-CONTRACT-v1.json)を参照。
固定ビルドの3水準は各36ファイル・39配信経路。実runnerは起動前に固定JSONと配信経路・元ファイル・SHA-256を照合し、
承認済みloopback originのGETに配信する。実測した初回ナビゲーションの9 URLは比較基準として使う。校正fixtureのHTTPは各0件。

| 判定 | runnerの処理 |
| --- | --- |
| BASELINE_MATCH | 通信・原票読戻し・片付けが揃った場合に他のゲートを評価する。 |
| COUNT_DEVIATION | 完全な原票の経路・回数・区間が基準から外れた場合、一次判定を保持し、所定の保存・片付けを完了して後続枠停止。 |
| NETWORK_AUDIT_FAIL | 許可違反を検知すると新規操作を拒否する。遅延本文の不一致も一次判定と採取済み原票を保持して後続枠停止。 |
| INCOMPLETE | 本文・イベント・対応根拠・保存・cleanupの不足を記録し、完了扱いを避けて後続枠停止。 |

推定したcache hitから不足したorigin原票を補わない。304の合成対照では、ブラウザ200・固定本文SHAと、
originの304・一致する条件付きリクエストのvalidatorとETagを照合する。同一URLとvalidatorの並行要求に
200と304が混在し個別対応を説明できない場合はINCOMPLETE。固定originは従来の200配信を維持する。

各枠の通信原票にはブラウザイベント、originイベント、本文、SHA-256、対応、位相、欠測理由を残す。
一次原票は排他的に保存し、開始済みの一次読取りが確定してからcleanupで読戻す。停止要求と終了完了は
workerと外側のPID監督の原票で確認する。割り当ては1170秒停止要求、1200秒最終打切り、猶予30秒を維持する。

## 本試行から切り離した対照

Playwright 1.56.1、WebKit 26.0（2215）、外部通信のないloopback名前空間。
固定ビルド3種類は各1回、新規コンテキストで同じURLに移動し、既定の `goto` 完了後
400 msまで観測した。既存配信と同じHTTP 200・Content-Type・Content-Lengthで返し、観測中の
要求を回数で拒否する制御は対照サーバーに入れていない。Swipe操作、一次判定、登録試行は実行していない。

- I0・I1・I2はブラウザの要求イベント、サーバー受信とも各9件。全件HTTP 200、同一経路の重複なし。
  静的な初期候補10 URLのうち `03~yq9q893hmn.js` は3ビルドとも観測されなかった。
  preloadとscriptに併記された `0ht900cau6_ur.js` は各1件だった。
- 合成302→200は中間・終点を別々に記録した。遷移先はBrowserContextの関連IDとサーバー受信で確認し、
  Locationヘッダーそのものの原票は取得していない。同一URLへのno-store取得2回は、ブラウザ・サーバーとも各2件。
- キャッシュ対照では同じscriptを2回実行したが、2回目の挿入時は両観測点とも増分0。
  別のfetch反復では3回ともサーバーに到達し、いずれも200だった。
- テストが明示する `If-None-Match` では、サーバーとページ内fetchに304、
  同じ要求のPlaywright responseイベントに200を記録した。この対照の挙動を製品枠へ適用しない。

対照原票ZIPのSHA-256は `d150dac1e7b2df9dfcdb34b3154215cd851c18cdba397b778a135708eafeb929`。
全14項目のCRC、同梱台帳に記載した13項目のSHA-256とサイズを照合した。

## v1適用前の停止と原票の経緯

原物基準 `f6ab3898597b468b3f47efca7459ba80c37041a3`。独立レビュー初版
`91ab01d99c19ab2ad8d43c8c94184a598ff0e99d` では回数規則の不一致、停止と一次保存の競合、
停止後のキャンセルを通信異常とする判定、中断原票の誤完了を再現した。

runnerは配信ポート確定後とブラウザ起動前に規則を原票へ保存・再読取する。通信異常では
新規操作と後続枠を止め、監督が停止要求とPID名前空間の終了を個別に記録する。
異常時の猶予は検知から最大30秒。1170秒の新規操作停止期限と1200秒の全体上限も適用する。
終了に伴う取消は通信異常と区別し、中断原票は未完了。一次保存と停止が重なった場合は、
読戻しで原物と一致した一次判定を要約へ反映する。
校正04の続行は従来どおり、4枠の独立読戻しと片付けの完了を必要とする。
登録票はHOLD。実行には新たなmanifest・runtimeハッシュの独立照合と、所有者の別途実行承認が必要。
