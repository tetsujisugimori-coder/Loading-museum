# 診断UI v2：同じ目標で操作する

目的は条件をそろえた証拠採取です。製品PASS・実機PASS・原因確定を自動生成しません。旧v1記録器・比較器・原証拠は変更していません。

## WindowsとiPhoneで開く
1. このPRの固定HEADを別フォルダへcheckout。Node 22以降で `npm ci`。
2. `node scripts/prepare-standard-touch.mjs`。原本とbuildが結合され、後から変更するとサーバーは拒否します。
3. PowerShellで `$env:DIAGNOSTIC_HOST='0.0.0.0'; node scripts/serve-standard-touch.mjs`。
4. PC自身で `http://localhost:4174/standard/` を確認。Windowsの `ipconfig` で同じLANのIPv4を調べ、iPhone通常Safariで `http://そのIPv4:4174/standard/` を開く。PCを起動したまま、同じWi-Fiに接続。ゲストWi-Fi、VPN、端末間通信遮断は別途確認。ファイアウォールを無断で無効化しない。localhostはiPhone自身を指すため使わない。

## 75%と値+75は違います
brightnessは−100〜+100、初期0です。正規化75%は実値+50、実値+75は87.5%位置です。初期目標は75%→+50。画面で両数値を表示します。目標と許容誤差（初期±1実値単位）は別です。許容誤差は目標到達の表示だけで、比較器の幾何条件を緩めません。

## 1試行
- 製品またはReactなしHTMLを開く。製品は展示室のImage Adjustmentを開く。
- 端末等を入力し、drag/tap、反復1〜3、目標を設定。同じブラウザ・画面向き・表示倍率・目標で対照を行う。
- 開始してREADYを確認。dragは現在位置のつまみから目標へ移動、離す。tapは目標のトラックを1回タップ。別試行として記録する。
- 現在値・最後の観測値・確定値・取消・イベント数を確認し封印。JSONを保存し、画面も撮影。失敗・取消・無イベントでも破棄しない。
- Resetはページ再読込で初期値0・履歴0へ戻す。封印後JSONを保存してからReset。旧試行を上書きしない。

## 診断限定条件
native inputのイベントハンドラは製品のまま。診断限定CSSで位置・大きさ・thumb20px・touch-action pan-yを両面に設定します。製品通常展示と同じスタイルだとは主張しません。記録パネルの更新は固定領域で行い、range幾何を変えません。横スクロールや倍率変化・Safariツールバー高さ差は記録に残します。座標式は20px thumb中心が動く範囲を使用し、実DOM値との照合が必要です。描画目盛りの75%とinput.valueを取り違えません。

## 記録と比較
schema `iad-standard-2` はv1と別契約。元の厳密v1比較器は不変です。v2比較は条件差の一覧であり、原因や実機PASSは出しません。入力座標の差を黙って許容せず表示し、結果値の差を比較不能条件にはしません。端末自己申告・UA・DPR・viewportを保存し、申告とUAの不一致も隠しません。isTrustedだけで物理入力と認定しません。

full/minimal/offは観測干渉の対照です。offにも診断の表示・開始終了snapshotはあり、完全無介入ではありません。通常展示は別の無注入対照。自動ブラウザで最終値一致を確認しても実機の計測中立性は未証明です。

既存実機原JSONは公開せず、PR #74の監査コメントから得た事実と新規自動試験を分けます。既存製品drag=75、plain=60は条件差を伴い、対比較不能。新UIによる実機4種類×3回はNOT_TESTEDです。
