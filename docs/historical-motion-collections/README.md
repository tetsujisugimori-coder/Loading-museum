# Issue #90：歴史的な動きの横断コレクション 第1便

## 位置付け
DIGITAL MOTION ARCHIVEは当面、歴史的なデジタルアニメーションの採取・再構成を優先する。待機画面に限定せず、GUI/CUI/混合を対象とする。既存13展示室と「歴史／現代」の入口を保全し、別の切り口による横断コレクションを追加する。

## 重複の扱い
1. **同一作品の複数掲載**は歓迎する。ひとつの既存作品に多数のテーマ別入口を設けられる。表示する「掲載数」は配置件数であり、固有展示数を加算しない。
2. **別版の独立採取**も認める。OS、時代、入力方式、演出、根拠の違いを観察する目的なら新しい永久IDの展示として採録できる。関連する旧作品への参照と違いを明記する。似ていることだけで却下しない。
3. `museumCatalog` の `room:id` は既存作品を指す参照識別子。安定ID・URL・本体の変更やコピーはしない。新規独立作品の追加は別便で登録・総数監査を行う。
4. 年代（確証のないものはUNKNOWN）、プラットフォーム、GUI/CUI、動作分類、操作目的、史料・再構成状態を別軸として扱う。
5. 既存展示を横断企画に採用しただけでは史実を再認定しない。`not-reviewed` は「この横断企画における根拠が未照合」を意味し、既存個別展示の史料状況まで否定するものではない。

## 初期3コレクション
- 端末のリズム：CUIの回転文字、文字プログレス、UNIX風ログイン、Linux起動ログ。
- 処理の進行を伝える：文字プログレス、ファイルコピー、コンパイル、Linux起動、Macintosh起動。
- GUIの直接操作：矢印カーソル、待機カーソル、Macintoshのウィンドウ操作、Finder操作。

**13掲載／11固有作品／3コレクション**（初期台帳）。文字プログレス・Linux起動ログは意図した重複掲載の正例。**全館の286固有展示と13室は不変**。作品の年代や史実根拠は原典調査待ちであり、ここでは新規に史実認定しない。

## 検証境界
- `app/data/historicalMotionCollections.ts` に加法的な分類台帳。`museumCatalog` の参照解決で実在・歴史区分・同一コレクション内重複拒否を確認。
- トップ入口では「掲載数」と「固有作品数」を分離表示し、実際の既存作品リンクを利用。
- 型検査・登録数/リンク/表示の専用テストは正式CIで確認。初回提出時の検証実績を先取りしてPASSとは書かない。
- PR #88 Stage CのHOLD、登録10枠、証拠原ZIP、既存診断器・runtimeには触れない。Draftで提出し独立レビューを待つ。マージと公開は別判断。

## 第2便以降
一次資料または実機由来の証拠を採取し、新しい歴史作品を少量ずつ追加する。例：BBS通信、転送プロトコルの表示、GUIの操作反応。ただし既存の抽象再構成（文字ログ等）と歴史的に特定できる表示は区別する。
