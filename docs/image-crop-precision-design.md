# P2-01：数値精度・境界の契約（実装前の選定）

2026-11-05 JST。レビュー対象と現PR/local HEADはともに`95ab616f961fcfb5af9ac393c44f33ead68d285b`、tree `dc9ebcc42c54142aa724ab0739998741737294e5`。mainは`8f065e0d0392b78b927d148648d0b77205ef979a`。開始時clean、PRはDraft、Issue #63 OPEN、レビュー/Conversationの投稿0件。依頼本文のP2候補を起点とし、製品変更前にモデル/ブラウザの再現器を作成した。

## 修正前の原因

UIの入力欄は`toFixed(6)`で内部値を失う。一方numericは、その表示を新しい値として厳密検証する。16:9では幅142.22222222222223→表示142.222222→高さ79.999999875となり拒否する。4:3は表示106.666667が受理されても、最初の再適用で幅/高さが変わる。1:1の80×80はこの問題が出ない。近い自由比率や元絵端の小数も6桁化で移動/変形し得る。

別に、浮動小数点の加算結果だけで右端/下端を見ると、厳密な二進数の和が端を超えても丸めで1000/700となる場合がある。入力許容差を広げる解決では、この拒否漏れをさらに増やす。再現・設計の両方で区別する。

## 方式比較

|B 表示6桁の丸めセルを入力検証と共有|半桁以内の境界snapなら再適用できるが、明示的に入力された同じ小さな違反と表示由来の誤差を区別する追加規則が必要|直前状態を参照して元値に戻す方式は入力が文脈依存。新規入力のsnapでは元の矩形が変わる|表示は短いが、同じ数値が状況で異なる意味になる。今回の契約には採用しない|

## 採用する契約

1. 編集用のX/Y/幅/高さは有限のJavaScript binary64値。入力欄は`String(value)`の最短往復表現で表示し、6桁へ丸めない。入力欄の値は同じbinary64値へ戻る。結果下の小数1桁は「概数」と明示して区別する。
2. 十進数と指数表記を扱う。数値変換で桁を落として別のcanonical decimal表記になる入力は拒否する。先頭/末尾の0、符号、等価な指数表記は正規化して比較する。例えば80.00と8e1は同じだが、79.999999999999999が80へ丸められる入力や1e-400の0化はエラー。負の0は座標0へ正規化。任意精度の十進数/分数ソルバーではない。
3. 固定比率は整数組(1,1)/(16,9)/(4,3)を共有。高さは幅×分母÷分子の一つの経路で導出し、表示の連動・数値入力・比率変更・角伸縮で共通利用する。高さ欄は従来どおり読取専用で、幅が権威値。比率違反の高さを独立採用しない。
4. 最小80と元絵内は入力値に対して厳密に判定し、入力を自動snapしない。右端/下端はTwoSumで丸め残差も確認する。実数としての十進表記ではなく、受理したbinary64座標の厳密な和が1000/700以内という契約。これより細かい十進数を無制限に扱う保証はしない。
5. pointer/比率変更で境界を生成する際は、有効範囲を満たす表現可能な上限/下限を用いる。除算の逆演算で上限を1 ULP超える場合は下側の隣接binary64へ、最小を下回る場合は上側へ進めて構成する。入力検証ではこの補正をしない。全座標を6桁化したり、許容差で外側を合格させたりしない。
6. 0移動の伸縮と同じ比率の再指定は元状態を保持。変更判定は数値の一致で行い、入力丸めによる変形をepsilonで隠さない。再適用・連続適用は各座標の厳密一致を検査する。
7. binary64で表せない厳密な有理比率を無限精度で描くものではない。比率の検査は有限回の乗除算から生じる数ULP以内を明示し、最小/端の入力判定には転用しない。SVG DOMの`baseVal.value`はブラウザでfloat32に丸まるため、論理座標は属性原文、実描画はscreen CTM/PNGで別々に検証する。

## 検証計画と保全

- モデル：実UI serializerを読み取る同一の再現器で、3固定比率×4隅の最小、自由/固定の最大、近接端、16回再適用、混合操作、明示的違反、2500操作を検査。端は製品TwoSumと異なるBigInt dyadic oracleで照合。
- ブラウザ：実マウスで四隅を最小へ動かし、表示欄を編集せず12回適用。入力値、矩形属性、preview/committed、通知、trusted submitを保存する。375/390/765/1280×両motion×Chromium/WebKitで実行。既存pointer取消/幅0/フォーカス/Pan & Zoomの検査は維持。
- 負対照：従来2 source故障とPNG故障を保持し、6桁化の再導入、最小緩和、丸めた加算だけの端判定を追加する。
- 旧証拠は変更しない。新規証拠は`docs/image-crop-precision-evidence/`。最初のJSON key順比較の誤り、SVG float32を論理値として読んだ再現器停止も、製品の不具合と区別して保持する。
