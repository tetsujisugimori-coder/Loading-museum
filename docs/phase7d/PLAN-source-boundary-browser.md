# Fixed isolated browser / Next-React validation plan (before execution)

This is validation-only, not the production108 experiment. Production remains disabled. No product file, deadline, expected value, or existing formal CI condition is relaxed. No trial retries or outcome-driven additions. Native crashes are NOT intentionally induced and will not be claimed from API rejection.

## Fixed allocation:14 slots, at most12 browser launches
Order: Chromium minimal model normal, controlled context.close rejection, real result-save rejection, controlled page interruption, unstarted sentinel; WebKit identical five slots; then Chromium Next/React normal, update-omission; WebKit Next/React normal, update-omission. Each launched slot uses a new browser/context. A sentinel is reserved and always remains NOT_TESTED after its preceding interruption. Expected injected failures do not prevent the next independent predeclared case. Unexpected setup/operation failure stops remaining launches; no reexecution.

- Real model normal: start, virtual clock100ms, single primary snapshot, persist primary, then cleanup.
- Cleanup: same operation and primary as normal; call actual context.close then throw CONTROLLED_CONTEXT_CLOSE_REJECTION. Browser.close and aggregate save must still happen; primary stays PASS while evidence becomes INCOMPLETE. This is controlled host API rejection after actual close, NOT an actual browser close failure/crash.
- Save fault: same operation and primary, then create a directory at the designated result.json pathname before final save. Actual filesystem write must fail and appear in aggregate/stderr; primary.json remains immutable. This is real controlled persistence failure, not alteration of a saved result.
- Interruption: actual page.close after runFor100 but before primary snapshot, then throw explicit controlled interruption. Primary remains absent, evidence INCOMPLETE. The following sentinel remains unstarted. This is controlled closure, NOT native crash or OS kill.

## Next/React product boundary
Two new isolated copies of the actual current product are built with existing instrumentBoundary groupC. Normal copy uses instrumentation only; fault copy adds existing applyBoundaryFault(status,update-omission), targeted at callback ordinal2. Original checkout/product is unchanged. Original/copied/transformed source files and full build output remain present with exact manifests; actual source snapshot is captured separately before use. No source is retroactively attached to previous CI.

Each engine runs the same inherited Status input sequence: expose details/mechanism, clock.install and pauseAt(Date.now()+1000), keyboard start →Loading, cancel →runFor4000 →Cancelled, Replay →runFor3000 →Success, select Error, Replay twice, runFor3000, single primary data-state read and synchronous exclusive persistence BEFORE boundary collection. Primary expected state remains Error for normal and fault. Fault detection requires product primary FAIL/Loading plus the update-omission fault-applied event from the instrumented actual React component. Missing prefix, missing fault marker, or missing evidence is INCOMPLETE/NOT_DETECTED, never success. Existing failure may recur in normal and will remain a normal FAIL, not a fixed product claim.

The C measurement hooks and trace/HAR can affect behavior; neutrality UNKNOWN. No claim of reproducing original six counterexample bytes, native crash, or root cause. Full Next build/provided HTTP resources and actual component execution provide a limited product-boundary check, not complete product acceptance or all React commit/DOM fault coverage.

## Evidence and judgment
Each slot preserves primary, operation error, independent cleanup/persistence errors, pageerrors, browser version, raw requested HTTP bytes/status/path/SHA, same-context full HAR and trace. Actual requested bytes must match fixed build outputs; source-to-build is a build provenance chain, not source/build byte identity for bundled React. Unrequested outputs are not claimed as executed. Every14slot record survives in aggregate; result-save failure is deliberately absent individually and must be detected.

Separate independent process audits source snapshot, result allocation/classification, raw HAR/HTTP/build correspondence and archive bytes/CRC. Negative controls cover altered/missing source/build/resource, unsupported conditions, missing primary/fault marker, incorrect classification and duplicate/missing slots. Normal controls must pass without weakening expected product behavior. Product outcome, evidence completeness, controlled-fault detection and CI conclusion are separate.

Estimated new outputs<3GiB including two isolated production builds; dedicated work/temp/evidence only, existing originals retained. Windows offline is not capacity or permission failure; Library alternative and Windows transfer are separate.

## Source capture order
Before either isolated build, capture the committed execution-input set to an exclusive pre-build-source directory and audit it in a separate process. Then build the two isolated copies. Prepare captures another actual-byte snapshot immediately before browser execution. The earlier and later snapshots are distinct; a post-build snapshot is not called build-time evidence. All new execution files must be committed before this sequence. The parent coordinator owns commit/push and reviews.

Browser/native cleanup hangs and OS kill are not induced; no host-deadline guarantee is claimed beyond recorded Playwright API timeout and actual observed completion. Controlled close failure is injected only after the real close completes. Missing cleanup completion is not proof of success; such execution would be incomplete. Real native crash remains NOT_TESTED.
