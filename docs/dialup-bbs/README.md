## 1. 採用方針
本企画「パソコン通信とBBSの時代：電話線の向こうに広がった世界」は、初期12候補を収集の出発点とし、上限とはしない。発見した歴史的な動きは候補ID、年代根拠、媒体、技術的特徴、既存作品との相違、権利状態を追記して段階的に採録する。
既存13展示室・286固有展示（企画開始時点の基準）と歴史／現代の分類、旧ID・URLを維持する。作品の横断掲載は本体の重複ではなく参照とし、総数へ二重計上しない。別の史料・条件での独立再現は新しい永久作品IDを付す。
動きの由来は「通信そのもの」「端末・掲示板機能」「意図的な芸術表現」の3軸で分ける。実際の史料・技術に裏付けられた部分と、推定した現代再現を混同しない。

## 3. 第1便の表示モデル
### 03 低速文字表示
1983年の雑誌『Personal Computer World』の記事は300bpsのBBS接続と7E1/8N1設定例を紹介する。展示はASCIIの架空テキストを300/1200/2400bpsで送り、バイト到着による表示を再現する。
通信時間 = 伝送ビット数 ÷ bps。8N1はスタート1 + データ8 + ストップ1の計10ビット/バイト。300bpsで100バイト送る最短の回線時間は約3.33秒。日本語の表示文字数をバイト数と取り違えない。実際の応答待ちや回線誤り、サーバー負荷は別モデルまたはUNKNOWNとする。baudとbpsも無条件に同一視しない。

### 04 日本語パソコン通信
1987年のNIFTY-Serve投稿ログの後年公開、および1989年のサービス情報を示す1990年白書を根拠に、当時の日本語通信が存在したことと、本文・見出し・改行表現を調べる。過去ログのHTML本文は当時の生バイト列や端末画面そのものではない。
ISO-2022-JPを記述するRFC 1468（1993年）はInternet mail/news向けであり、NIFTY-ServeやPC-VANの通信文字コードを確定する証拠にしない。文字コードは作品・資料ごとに確認し、原バイト未取得ならUNKNOWNとする。架空の日本語文章と説明用モデルで初期実装を行い、元投稿を無断転載しない。

### 05 掲示板連続スクロール
1979年DEC VT100 User Guideには行単位で切り替わるjump scrollと滑らかに移動するsmooth scrollの説明がある。展示では架空の掲示板表示に対して2方式の相違を見せる。ただし個々の日本のBBSがVT100 smooth scrollを採用したと主張しない。通信速度による到着タイミングと端末による行更新は別々に扱う。

## 4. 共通エンジンの責務の分割
作品と史料のメタデータ
  ↓
シナリオ（バイト列・意味イベント・条件・限界）
  ↓
仮想時計／送受信スケジューラ
  ↓
増分復号器（分割到着バイトを保持）
  ↓
端末状態機械（カーソル／セル／改行／折返し）
  ↓
スクロールポリシー（jump/smooth）
  ↓
表示アダプタ（安全なテキスト表示、将来のCanvas等）
  ↓
共通観察UI（再生・停止・速度・即時表示・Reset）

- SourceRegistry：sourceId、発行者、年月、当時の資料か後年再掲か、根拠箇所、原画像／生バイトの確認、権利、取得と保全の状態を記録。
- ScenarioRegistry：候補ID、将来の永久作品ID、根拠ID、表示設定、演出分類、限界とモデル条件を記録。12件を固定長として扱わない。
- TransportClock：bps、dataBits、parity、stopBitsを入力とし、文字数でなく送信バイトおよび伝送ビット単位で到着時刻を計算。歴史的通信速度と来館者の再生倍率を区別。
- StreamingDecoder：複数バイト文字、ESC文字集合切替が途中で分割されても保持する。Shift_JIS／JIS系／EUC-JPなどは証拠があったシナリオだけ有効化。
- TerminalCore：設定可能な行列（例として80×24、必須の史実値ではない）、CR／LF／CRLF／BS／TAB、カーソル、行の最終端、全角2セル・折返し、下端スクロールを論理状態として処理。
- ScrollPolicy：jumpとsmoothは描画方式の設定。史料に裏付けられないXON/XOFF等の動きを作品全体の歴史的事実にしない。
- Renderer：端末状態から描画し、本文をHTMLとして実行しない。第2便のANSIや第4便のRIPscripは厳格な命令許可リストを持つ追加処理として設計。
- PlaybackController：再生、一時停止、再開、速度変更、単位ステップ、seek、即時表示、Reset。旧再生世代を失効させ、画面切替や停止後のイベントが後続展示を上書きしない。
- Accessibility：連続する全画面更新を読み上げ続けさせず、本文・直近イベント・状態を別に確認できる。reduced-motionでは過度な動きを省きつつ、結果・手動観察を保持。音は明示的な操作まで再生しない。

## 5. シナリオ契約（設計）
Scenario の必須概念：
- id、version、sourceIds、provenanceState、limitations
- transport：bps、dataBits、parity、stopBits、direction
- encoding：name、evidenceStatus
- terminal：columns、rows、wrap、scrollPolicy
- events：virtualTime、bytePayloadまたはsemanticEvent、説明
- controls：pause、seek、instantReveal等
生バイトが実存しない教材イベントは「raw capture」と表記しない。seek/Resetは復号途中・行送り・時刻を含む初期状態から再実行可能にする。

## 6. 候補の追加と資料収集
1. 発見したら候補IDを発行し、初期12候補の番号や既存展示の永久IDを変更しない。
2. 記録媒体、発行・作成年、原著者、歴史的画面と後年の説明、当時の文字コード・速度・端末機種、実物の有無を確認する。
3. 根拠の強さを作品の各部分に付す。「source-backed」「conceptual-reconstruction」「creative-comparison」「not-reviewed」を区別。
4. 閲覧・ダウンロード可能でも再配布許諾とは限らない。実在投稿の本文や識別情報を展示に無断複製しない。
5. 原証拠の保存済・ハッシュ一致を主張する場合は、承認済み保管先からの再取得照合を別作業として要求する。未実施はNOT_TESTED。

## 7. 実装工程へ移る際の最小試験
- 300/1200/2400bps、7E1/8N1、複数バイト文字の途中受信、ESCの途中受信、壊れた入力。
- CR、LF、CRLF、BS、TAB、折返し、最終行移動、jump/smoothの最終端末状態が一致すること。
- pause/resume/seek/instant/resetと画面切替時の旧タイマーの失効、順序逆転や二重開始の防止。
- 外部電話回線/BBSへ実接続しない。HTML注入を許さない。史料の権利不明は公開禁止。
- Chromium/WebKit、375/390/765/1280px、動き軽減、キーボード、画面読み上げを実装後に評価。実機Safari/VoiceOverは実測までNOT_TESTED。
